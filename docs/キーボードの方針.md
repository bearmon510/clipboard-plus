# 専用キーボードの方針

2026年11月18日。利用者が、11月15日に見送った専用キーボードを作ることにした。作る時期と形は、Claude・Gemini（4 Carbon）・GPT（6.2 Astra、6.2 Sol）の会議で整理し、利用者が決めた。

## 決めたこと

- **役割。** 普段の日本語入力は純正キーボードのまま使う。clipboard+ のキーボードは、地球儀キーで切り替えて履歴とテンプレートを使うためのもの。
- **時期。** 段階5で、共有拡張と一緒に作る。段階4（PCの履歴の窓とWin+V）の後。TestFlightは5+6でまとめて出す。
- **フルアクセス。** あってよい（利用者の判断）。ただし、審査ガイドライン4.4.1により、フルアクセスがオフでも動く必要がある。オフのときは履歴とテンプレートの挿入だけにする。
- **開いたときのタブ。** 地球儀キーで clipboard+ に切り替えたとき、最初に「履歴」と「テンプレート」のどちらを出すかを、本体の設定で選べるようにする。外で履歴を人に見られたくない場面への配慮。
- **物理キーボード。** iPadで物理キーボードは使わない。物理キーボードをつないだときの扱いは作り込まない。
- **署名。** App Groupやキーボードの App ID がCIの自動署名で登録できなかったときは、利用者がApple Developerのサイトで登録する。

## 会議で確かめたこと

確かなこと：

- 純正キーボードに、他社のアプリが機能を足す方法はない。キーボード拡張は、純正と丸ごと切り替える方式だけ。[Appleのキーボード作成ガイド](https://developer.apple.com/documentation/uikit/creating-a-custom-keyboard)
- キーボード拡張は、入力欄が出ていて、そのキーボードが選ばれている間だけ動く。裏での常時監視はできない。既定のキーボードにしても同じ。そのため、キーボードを取り込みの入り口にしても、取れるのは開いた時点でクリップボードにある最新の1件だけ。[拡張の動き方](https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/ExtensionOverview.html)
- フルアクセスなしでは、クリップボード（`UIPasteboard.general`）の中身を読めない。App Groupの共有コンテナは、読めるが書けない。フルアクセスがあれば、どちらもできる。フルアクセスをオンにするとき、iOSが入力内容を送信し得るという警告を出す。[フルアクセスの仕様](https://developer.apple.com/documentation/uikit/configuring-open-access-for-a-custom-keyboard)
- パスワードなどの入力欄と電話番号の入力欄では、純正キーボードに切り替わる。アプリによっては、他社のキーボードを使わせない。
- 審査ガイドライン4.4.1は、文字の入力機能、次のキーボードへの切り替え（地球儀キー）、フルアクセスやネットワークなしでの動作を求める。[審査ガイドライン](https://developer.apple.com/app-store/review/guidelines/#extensions)
- 日本語を打つキーボードを自分で作るなら、かな漢字変換と学習は、オープンソースの部品（AzooKeyKanaKanjiConverter、MITライセンス、辞書はApache-2.0）を使える。ただし、未確定の文字や変換候補の画面は自分で作る必要があり、純正とは別の使い心地になる。今回は作らない。

推測（実機で確かめる）：

- キーボード拡張の中で、標準のペーストボタン（`UIPasteControl`）が使えて、「ペーストの許可」の確認なしに中身を受け取れるか。使えない場合、直接読むと確認が出る場合がある。
- フルアクセスがあるとき、`changeCount` がキーボード拡張の中で正しく変わるか。
- キーボード拡張のメモリの上限（公開されていない）の中で、300件の一覧が問題なく動くか。

## 作るもの（段階5）

段階5は、次の順に進める。

1. **署名の確認。** 最小のキーボード拡張と共有拡張のターゲット、App Groupを足し、TestFlightのワークフローで、配布用の書き出しまで通るかを確かめる。CIでのコンパイルだけでは合格にしない。通らなければ、利用者に登録を頼む。
2. **共有の土台。** 本体が、キーボード用の一覧（文章・URL、PCから届いたものも含む、テンプレート）を App Group の共有コンテナにJSONで書き出す。拡張から本体への「受け取り箱」も、共有コンテナに作る。
3. **キーボード（フルアクセスなしで動く部分）。** 「履歴｜テンプレート」のタブ。タップすると `textDocumentProxy.insertText` で入力欄に入れ、クリップボードは使わない。地球儀キー、空白、削除、改行に加えて、簡単な英数字のキー面を置く（4.4.1の「文字の入力機能」への対策）。iPhoneとiPadの両方に合わせる。
4. **キーボード（フルアクセスがあるとき）。** 「今のコピーを保存」ボタン。標準のペーストボタンで受け取れるなら、それを使う。受け取った文章・URLは受け取り箱に入れ、本体が次に動いたときに履歴へ入れてPCへも送る。フルアクセスがオフのときは、このボタンを出さない。
5. **共有拡張。** 同じ受け取り箱を使う。

後に回すもの：キーボードからの画像とファイルの挿入（`insertText` では渡せない）、キーボードの中での検索と編集、普段の日本語入力（かな漢字変換）。
