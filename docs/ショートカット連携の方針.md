# ショートカット連携の方針

2026年11月16日。利用者の要望は、iPadの「ショートカット」から、clipboard+の文字の切り取りか画像の切り取りへ一気に移れるようにすること。ショートカットの「スクリーンショットを撮る」と組み合わせ、どこまで自動にできるかを考える。

## 前提：できないこと

- **アプリからスクリーンショットを撮る公開APIはない。** 撮るのはショートカットの「スクリーンショットを撮る」か、iPadの操作に任せる。
- **ショートカットの中に、範囲をドラッグする画面は置けない。** iOS 26からApp Intentsの結果（スニペット）にボタンとトグルを置けるが、操作は `Button(intent:)` などで別のインテントを呼ぶものに限られる。範囲を指で選ぶには、clipboard+を開く必要がある。
- **元のアプリへ自動で戻す公開APIはない。** clipboard+を開いた後は、利用者が戻る。Slide Overや小窓で開けば、戻る操作はいらない見込み（実機で確認する）。

## 使い方は4段階

ショートカットの「スクリーンショットを撮る」は、写真に保存しない。写真へのアクセスもいらない。0.9.0のスクリーンショットから開く経路（写真から拾う）と比べ、写真にスクリーンショットがたまらないことと、文字と画像を呼び出し方で分けられることが利点になる。

| | 流れ | clipboard+を開くか | 利用者の操作 |
| --- | --- | --- | --- |
| A. 範囲を選んで切り取る | スクリーンショットを撮る → 画面を切り取る（方式：文字／画像） | 開く。指定した方式の切り取り画面で開く | 範囲を選ぶだけ |
| B. 画面の文字から選ぶ | スクリーンショットを撮る → 画像の文字を読み取る（行ごと） → リストから選択（複数可） → clipboard+に追加 | 開かない | 一覧で行を選ぶ |
| C. 画面の文字を全部コピー | スクリーンショットを撮る → 画像の文字を読み取る（コピーして履歴に保存） | 開かない | なし |
| D. 応用 | Cの後に、Apple Intelligenceの「モデルを使用」で住所や電話番号だけを取り出す、翻訳するなど | 開かない | なし |

- Aが今回の要望の中心。Bは、アプリへ移らずに済む。行の単位で足りる場面（電話番号、住所、コード）では、Aより速い。
- 「リストから選択」はショートカットに元からある操作なので、clipboard+側で一覧の画面を作らなくてよい。
- Dはclipboard+が新しく作るものはない。使い方の画面で例として紹介する。端末とOSでの動作は実機で確かめる。

## 呼び出し方

| 呼び出し方 | 割り当てられる数 | 備考 |
| --- | --- | --- |
| AssistiveTouchのカスタムアクション | 3つ（シングルタップ、ダブルタップ、長押し） | 画面に常に浮かぶボタン。ショートカットを選べるかは実機で確認する |
| Apple Pencil Proの握る操作 | 1つ | 「設定」→「Apple Pencil」→「握る」で「ショートカット」を選ぶ（Appleの資料で確認） |
| コントロールセンターの「ショートカット」 | 置いた数だけ | どの画面からでも開ける |
| ホーム画面のアイコンやウィジェット、Siri、Spotlight | 任意 | 「Hey Siri、文字を切り取る」など |

おすすめの割り当て：AssistiveTouchのシングルタップを「文字を切り取る」（A・文字）、ダブルタップを「画像を切り取る」（A・画像）、長押しを「画面の文字を選ぶ」（B）にする。

## clipboard+で作るもの

### 第1段階（0.10）：切り取りへ直接入る

1. **「画面を切り取る」を強くする。** 方式（文字／画像）の引数を追加する。受け取った画像で、その方式の切り取り画面をすぐ開く。ほかのシートが出ていれば閉じてから開く（0.9.0の `openFromOutside` を使う）。方式を省いたら、設定の方式に従う。
2. **「画像の文字を読み取る」を新設する。** アプリを開かずに動く。画像を受け取り、Visionで読み取った文字を返す。返し方は「まとめて」か「行ごと」（リスト）を選べる。「コピーして履歴に保存」をオンにすると、clipboard+の履歴に入れてクリップボードにも置く。
3. **「clipboard+に追加」を新設する。** アプリを開かずに動く。文章か画像を受け取り、履歴に入れる。「クリップボードにもコピー」を選べる（既定はオン）。Bの最後と、共有シートから送るショートカットに使う。共有拡張を作らなくても、共有シートからclipboard+へ送れるようになる。
4. **App Shortcutsを登録する。** `AppShortcutsProvider` で、ショートカットアプリ、Spotlight、Siriに最初から出す。言い方の例は「clipboard+で文字を切り取る」。
5. **使い方の画面に、A・B・Cの作り方と、AssistiveTouchとApple Pencil Proの割り当てを書く。**

### 第2段階（0.11、テンプレートと一緒に）：履歴をショートカットから使う

- 履歴を `AppEntity` にし、「最新の履歴を取り出す」「履歴を検索する」「ピン留めを取り出す」「履歴をコピーする」を作る。テンプレートを入れるときに、テンプレートを名前で貼る操作も足す。

### 第3段階（0.12、ウィジェットと一緒に）：コントロールセンター

- 拡張のターゲットとApp Groupを足すときに、コントロールセンターのボタンを作る。ただし、ボタンからはスクリーンショットを撮れないので、AとBはショートカットのコントロールで呼ぶほうがよい。clipboard+のボタンは、直接の取り込みで切り取りを始める用途にとどめる。

## 技術メモ

- **アプリを開くインテント。** iOS 26で `openAppWhenRun` は非推奨になり、`supportedModes`（`IntentModes`）に置き換わった。最低対応はiOS 17なので、`openAppWhenRun` を残す。iOS 26以降で `supportedModes` を足すかは、実装時にSDKの宣言で確かめる。
- **開かないインテント。** 処理はclipboard+のプロセスで動く。履歴の保存とクリップボードへの書き込みは `ClipboardMonitor.saveCaptured(text:)` と `saveCaptured(pngData:)` を使い、自分で書いた内容を二重に記録しない。インテントから `ClipboardMonitor` に届く経路（共有のインスタンスか `AppDependencyManager`）を用意する。
- **裏での読み取り。** `saveCaptured` はコピーの前にクリップボードを一度読む。アプリが裏にいるときにこの読み取りが拒否されたり、許可を求められたりしないか確かめる。問題があれば、インテントからのときは読み取りを省く。
- **時間。** Visionの読み取りは画面1枚で数百ミリ秒から数秒。インテントの制限時間に収まる見込みだが、計測ログに時間を残す。
- **スクリーンショットの解像度と向き。** ショートカットから受け取った画像は、`CaptureSource` で向きを直してから使う（今と同じ）。

## 実機で確かめること

1. ショートカットをAssistiveTouchから動かしたとき、「スクリーンショットを撮る」に、ショートカットの実行表示やAssistiveTouchのボタンが写らないか。
2. Aでclipboard+が開くとき、Slide Over、小窓、全画面のどれで出るか。clipboard+をSlide Overに置いていた場合はどうなるか。
3. ボタンを押してから切り取りの画面が出るまでの時間。
4. B・Cで、アプリが裏にいてもクリップボードに書けて、履歴に入るか。許可を求める表示が出ないか。
5. AssistiveTouchのカスタムアクションで、ショートカットを選べるか。

## 0.9.0の経路との関係

写真から拾う経路（スクリーンショットで切り取りを開く）は残す。普段のスクリーンショットの操作だけで使え、ショートカットを作らなくてよい。ショートカットの経路は、文字と画像を呼び出し方で分けたい人と、写真にスクリーンショットを残したくない人に向く。使い方の画面では両方を案内する。

## 実装メモ（0.10.0）

今回の依頼に合わせ、画面以外の第1段階と履歴連携を実装した。画面、共有の切り取りインテント、CaptureInbox、コントロールセンター拡張、XcodeGen設定、CI設定は変更していない。

### 実装した経路

- `ClipboardMonitor.shared` を画面の `@StateObject` と新しいインテント・エンティティクエリで共有する。`AppDependencyManager` は使わない。共有インスタンスの生成はMainActorに限定し、画面なしの起動では自動監視を始めず、最初の `updateScene("active")` で記録設定に従って再開する。`XCTestConfigurationFilePath` がある場合は記録の既定値を登録しない、という従来の扱いを維持した。
- 各処理は `performShortcut` から入り、`historyForShortcuts()` を待つ。ストレージの直列キューで初期読み込み・先行書き込みの後に読み直し、メインキューに履歴を反映してから続行する。保存期限も既存の読み込み処理に従う。読み込みに失敗した場合は、空の結果を成功扱いで返さず、日本語のエラーを返す。
- 保存用の `HistoryStore.saveFromShortcut` はDBへの保存完了を返す。`ClipboardMonitor.saveFromShortcut` はその完了を待ち、必要な場合だけ既存の `copy` を呼ぶ。コピーしない場合は履歴だけに保存する。新しい保存要求の失敗は未保存キューに残さず、Shortcutsへ失敗を返した後に自動再試行で保存されることを避けた。通常の自動記録の再試行は従来どおり。
- `ReadTextIntent` / `ReadTextLinesIntent` は `IntentFile` の画像を受け、メインスレッド外で `CaptureSource` による向き補正と既存の `TextRecognizer` を実行する。上から下、同じ行では左から右へまとめ、前後の空白・空行を除く。文字がなければ日本語のエラー。文字列または `[String]` を返し、コピー・保存の既定値はオフ。
- `AddToHistoryIntent` の文章は `[String]?`。空白だけの要素を除き、残った要素の字下げや内部改行を保って改行結合する。画像は向きを直してPNGに変換し、既存の画像容量制限・サムネイル・同一画像の統合処理を使う。コピーの既定値はオン。文章と画像の両方があれば各1件を保存し、画像をコピーする。この動作はShortcutsのアクション説明にも記載した。
- `HistoryEntryEntity` はID、本文、種類、保存日時、ピン留め、任意の画像ファイルを公開する。表示名は本文の最初の空でない行（最大60文字）か「画像 幅×高さ」。画像は元画像のURLを使う `IntentFile` とし、一覧取得時の全画像のメモリ展開を避ける。`removedOnCompletion` は既定のfalseを保ち、履歴の元ファイルをShortcutsに削除させない。
- `entities(for:)` は指定されたIDの順で返し、削除済みIDを省く。候補は新しい順に最大20件。`entities(matching:)` は既存の `HistoryFilter` と同じ検索規則で全一致候補を新しい順に返す。検索語の前後空白を除去し、大文字小文字を区別しない部分一致。空の語句は画像を含む全種類、空でない語句では画像を対象外にする。
- `GetHistoryIntent` / `SearchHistoryIntent` の件数は既定1、1〜50。パラメータの範囲指定に加え実行時にも上下限を適用する。順序は既存履歴と同じ `lastCollectedAt` 降順、同時刻はID降順。種類は既存の5種類に対応する。`CopyHistoryEntryIntent` はIDで現在の履歴を再確認してコピーし、削除済み項目を古いエンティティ本文からコピーしない。
- `ClipboardPlusShortcuts` は4件。「文字を切り取る」「画像を切り取る」は既存の `StartCaptureIntent(mode:)` を使用する。「最新の履歴をコピー」は引数不要の `CopyLatestHistoryIntent`、「履歴を検索」は `SearchHistoryIntent` を使う。全フレーズに `\(.applicationName)` を含め、`shortTitle` とSF Symbolを指定した。新しい7インテントはすべて `openAppWhenRun = false`。

### バックグラウンドでの読み取りと計測

ショートカットが明示的に渡した内容を保存・コピーする際、既存クリップボードを読む必要はない。許可表示やバックグラウンドの読み取り拒否を避けるため、インテント実行中は `readBeforeCopy` とコピー後の読み返しを省く。定期確認・scene変更による読み取りも、非同期処理中を含めカウンターで抑止する。書き込み後のchangeCountを記録して、自分の書き込みをもう1件として取得しない。文章については未処理の自己コピー印を残さず、後から他アプリで同じ文章をコピーした場合は通常どおり記録できるようにした。インテントのコピーで上書きされる前の内容は、この経路では新たに履歴へ取り込まない。

`MeasurementLog` に新しい各インテントとクエリの開始・終了、インテント名、所要ms、成否を記録し、終了ログのflushを待って返す。計測のdetailsには入力画像、検索語、エラー由来のファイルパスを入れない。保存・コピー自体のログは既存の方式に従う。変更禁止の `StartCaptureIntent` / `CaptureRegionIntent` 本体には計測を追加していない。

### HistorySourceと保存形式の互換性

今回は `.shortcut` を追加せず、利用者が明示的に追加する既存の `.manual` を使用した。SQLiteの `source` は文字列で追加自体は可能だが、従来の `HistoryDatabase.rows` は未知のrawValueで `invalidRow` を投げ、`HistorySource` のCodableデコードも未知の値を拒否する。したがって新しい値を書いたDB・JSON・バックアップを旧版が読む互換性は保てない。さらに画面側に `HistorySource` の全ケースを列挙したswitchがあり、今回の変更禁止範囲に影響する。

DBスキーマ、JSON書き出しのformatVersion 2、バックアップのformatVersion 1、および既存の4つのrawValueは変更していない。ショートカット経由かどうかはインテントの計測ログで確認する。XCTestには既存全sourceのDB再読み込み・書き出し・画像を含むバックアップ／復元と、未知の `shortcut` が従来の読み込み規則で拒否されることを追加した。

- 文章と画像の2件保存は一括トランザクションではない。後半の保存やコピーに失敗した場合、先に完了した履歴は残る。画像エンティティは履歴ファイルの参照なので、後続アクションが読む前に履歴が削除・期限切れになった場合の受け渡しは保証しない。

## 0.10.0の実機試験の後の判断（2026年11月16日）

- **メインの経路は「スクリーンショットを撮る」→「画面を切り取る」のショートカット。** 利用者がAssistiveTouchから動かして、これが最も使いやすいと判断した。使い方の画面と、履歴が空のときの案内はこの経路を先頭にした。
- **画面録画で直接取り込む機能は、PiPと同じく開発者向けの設定の奥へ移した（0.11.0）。** 既定はオフ。オフのとき、上の「文字」「画像」のボタンは出ない。`StartCaptureIntent` はショートカットアプリに出さず（`isDiscoverable = false`）、App Shortcutsからも外した。0.10.0で作ったショートカットから呼ばれた場合は、使い方の画面を開く。コードは残してある。
- **コントロールセンターの拡張（`ClipboardPlusControls`）は削除した。** ボタンは直接の取り込みを始めるだけで、スクリーンショットを撮れなかったため。コントロールセンターからは、iPadの「ショートカット」のボタンで利用者のショートカットを呼ぶ。`APP_BUNDLE_ID` の変数は、今後の拡張のために残す。
