# clipboard+ PiPの技術検証

2026年11月14日。利用者は、clipboard+を常に画面の一番上に出しておきたい。Slide Overは開いている間だけ収集でき、隠すと止まり、開き直すと解除される（[レビュー結果と試作方針](レビュー結果と試作方針.md)の「2026年11月14日の見直し」）。そこで、PiP（ピクチャ・イン・ピクチャ）の小窓で同じことができるかを、小さな試作で確かめる。

## 確かめること

1. **裏での収集。** PiPを出している間、全画面の別のアプリでコピーした内容を、0.5秒ごとの定期確認で全件取り込めるか。iPadOSが裏のアプリにクリップボードの読み取りを許すかは分かっていない。許可のダイアログの出方も見る。
2. **最前面の表示。** PiPの小窓に、最新の履歴が表示され続けるか。小窓を画面の端へ隠したときも収集が続くか。
3. **小窓での操作。** 小窓の中身に触れたときに何が起きるか。PiPでは中身へのタップは届かず、システムの再生操作だけが出ると見込んでいる。再生・一時停止のボタンを、記録の開始・停止に割り当てて使えるかを確かめる。
4. **続けて使えるか。** 30分ほど出したままにしたときの電池の減り、発熱、PiPが勝手に閉じないか。

App Storeの審査で通るかは、この試作では分からない。動画でない内容をPiPで出し続ける使い方は、審査ガイドライン2.5.4（バックグラウンドの用途）で問題にされる恐れがある。TestFlightの内部テストは審査を受けないので、検証はできる。

## 試作の作り

- **初期設定ではオフ。** 設定に「PiPで最前面に表示（試験中）」を足す。オフの間は、これまでの動作を一切変えない。
- **映像として描く。** 最新の履歴3件（文章は冒頭2行、画像は「画像」と大きさ）と、記録の状態、取り込んだ件数を1枚の画像に描き、`AVSampleBufferDisplayLayer` に映像の1コマとして流す。内容が変わったときと、1秒に1回、新しいコマを流す。
- **PiPの開始。** `AVPictureInPictureController`（`ContentSource(sampleBufferDisplayLayer:playbackDelegate:)`）を使う。本体の画面にPiPの元になる小さな表示と「PiPを開始」ボタンを置く。アプリが裏へ回ったときに自動で始まる設定（`canStartPictureInPictureAutomaticallyFromInline`）も有効にする。
- **再生・一時停止のボタン。** 一時停止で記録を停止し、再生で記録を開始する。終わりのない映像として扱う。
- **必要な設定。** `UIBackgroundModes` に `audio`（音声・AirPlay・PiP）を足し、オーディオセッションを `.playback` にする。音は出さない。
- **計測ログ。** PiPの開始・終了・失敗の理由、定期確認が裏で動いた時刻、裏での読み取りの成否を記録する。

## 合格の目安

1. PiPを出したまま、全画面のSafariで試験ページの20件を約1秒間隔でコピーすると、20件が順番どおり残る。
2. 小窓に最新の項目が表示され、コピーのたびに1秒以内に変わる。
3. 小窓を画面の端に隠しても、収集が続く。
4. 30分出したままでも、PiPが勝手に閉じず、電池の減りが利用者にとって許容できる。

1が満たせない場合（裏ではクリップボードを読めない場合）は、PiPは表示だけの役割になり、収集には使えない。その場合はPiPを採用せず、共有拡張へ進む。
