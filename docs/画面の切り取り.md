# clipboard+ 画面の切り取りと文字の読み取り（0.7.0）

2026年11月15日。利用者から、WindowsのWin+Shift+Sのように「1回のタップで範囲選択に入り、選んだ範囲の文字だけを読み取る、または選んだ範囲を画像にする。どちらもclipboard+に保存する」機能の要望があった。ショートカットに頼らない形が望ましい、という希望も添えられていた。

## iPadOSでできること、できないこと

- **ほかのアプリの画面を、アプリが自分で撮ることはできない。** 例外は画面の録画・配信の仕組み（ReplayKitのブロードキャスト）だけである。これは利用者が毎回システムの画面から配信を始める必要があり、配信中は録画中の表示が出続け、電池も使う。1枚撮るための手段としては重すぎるので採用しない。
- **ほかのアプリの上に、操作できる画面を重ねることもできない。** PiPの小窓は重なるが、中身には触れない。範囲を選ぶ操作は、iPadOSの画面かclipboard+の画面の中で行うしかない。
- **スクリーンショットを撮れるのは、iPadOSと「ショートカット」アプリ。** ショートカットには「スクリーンショットを撮る」があり、撮った画像をアプリへ渡せる。

このため、「どの画面からでも1回のタップで始める」には、スクリーンショットを撮る役をショートカットに頼むしかない。範囲の選択、文字の読み取り、保存は、すべてclipboard+の中で行う。

## 2つの入口

どちらも、同じ切り取りの画面と同じ読み取りの処理を使う。

### 準備なしで使える入口

1. iPadのスクリーンショットを撮る（ボタン、または画面の隅からのスワイプ）。
2. 左下に出る小さな画像をタップし、枠の角を引いて範囲を決める。
3. 「完了」→「コピーして削除」を選ぶ。clipboard+が自動で履歴に取り込む（画面に出ているか、PiPの小窓を出している場合）。
4. 文字がほしいときは、履歴の画像の「⋯」から「文字を読み取る」を選ぶ。範囲を選び直したいときは「切り取る…」を選ぶ。

### 1回のタップで始める入口

clipboard+はショートカット用のアクション「画面を切り取る」（`CaptureRegionIntent`）を持つ。画像を受け取ってアプリを開き、切り取りの画面を出す。

1. 「ショートカット」アプリで、「スクリーンショットを撮る」→「画面を切り取る」の2つを並べたショートカットを作る。
2. それを、AssistiveTouchのカスタムアクション、コントロールセンター、Apple Pencil Proのスクイーズなどに割り当てる。
3. 割り当てた操作をすると、その時点の画面が止まったように表示される。範囲を選んで「文字を読み取る」か「画像で保存」を押す。

使い方は、アプリの「⋯」→「画面の切り取り…」にも書いてある。

## 切り取りの画面

- スクリーンショットを窓いっぱいに出し、全体を少し暗くする。止まった画面の上で選んでいるように見せる。
- ドラッグで範囲を選ぶ。選んだ後は、角を引くと大きさを変えられ、内側を引くと動かせ、外側を引くと選び直せる。タップすると選択を外す。
- 範囲を選ばなければ、全体が対象になる。
- 「文字を読み取る」：選んだ範囲の文字を読み取り、履歴に保存してクリップボードにも入れる。読み取った文字を表示し、続けて別の範囲を選べる。
- 「画像で保存」：選んだ範囲をPNGにして、履歴に保存してクリップボードにも入れ、画面を閉じる。

保存した項目の取り込み方は「切り取り」（`HistorySource.capture`）とする。

## 文字の読み取り

Visionの `VNRecognizeTextRequest`（精度優先、日本語と英語）を使う。処理は端末の中だけで行い、画像や文字を外へ送らない。読み取った断片は、上から下、同じ行の中では左から右の順に並べる。縦書きの並べ替えには対応していない。

## 実機で未確認の点

- ショートカットの「スクリーンショットを撮る」に、AssistiveTouchのボタンやショートカットの実行表示が写り込まないか。
- ショートカットからclipboard+が開いたとき、窓の大きさがどうなるか。clipboard+を小窓で使っている場合、スクリーンショットは小さく表示され、細かい範囲を選びにくい可能性がある。その場合は拡大の操作を足す。
- 日本語の読み取りの精度と、かかる時間。
- 切り取った後、元のアプリへ戻る操作の手数（画面左上の「◀ 元のアプリ」）。
