# clipboard+ 試作1の実装方針

2026年11月14日。[レビュー結果と試作方針](レビュー結果と試作方針.md)の手順1「文章だけの実機試作」を実装へ移すための方針。Codexのレビュー1回分を反映した。

ビルドと実機確認は未実施。以下は採用する案で、iPad上で動くことを確認できた項目はまだない。

## 範囲

手順1だけを作る。1列の履歴、記録の開始・停止、手動保存、タップでコピー、メモへのドラッグ、履歴の個別削除と全消去、計測ログとその消去。

検索、ピン留め、再起動後の保持、URL・画像、共有拡張、キーボード、PiPは含めない。手順1の合格条件（20件が順番どおり各1回残り、途中の1件をメモで再利用でき、許可操作を繰り返さない）を満たすか、満たさない条件を切り分けられたら次へ進む。

## 採用する案

| 項目 | 案 | 理由 |
| --- | --- | --- |
| プロジェクト形式 | `app/project.yml` に定義を書き、GitHub Actions上でXcodeGenがXcodeプロジェクトを生成する。生成物はコミットしない | `.xcodeproj` は手で書き換えにくく、Macがないと開けない。テキストの定義ならWindowsで編集・レビューできる。手順3で共有拡張・キーボードのターゲットを同じ定義に足せる |
| 実機への導入 | GitHub Actionsで署名してTestFlightへ送り、iPadのTestFlightアプリから入れる | 利用者はApple Developer Programに加入済み。収集の挙動を、配布するアプリと同じ形で測れる |
| Swift Playground | 補助に使う。画面の見た目の確認など、TestFlightの往復を待ちたくない場面で使う | Playground内で動くアプリの貼り付け許可の扱いが、単独のアプリと同じかは未確認。収集の測定には使わない |
| 画面とAPI | 画面はSwiftUI、クリップボードはUIKitの `UIPasteboard`。外部ライブラリは使わない | 依存物の取得・ライセンス確認を試作から外す |
| OS下限 | `Package.swift` はiOS 17.0を指定 | 候補として残した下限に合わせる。確認できるのは主端末だけ |
| 履歴の保存 | メモリ上だけ。SQLiteは手順2で導入 | 手順1は収集と再利用の可否を測る。保持は手順2の合格条件 |
| 計測ログ | メモリに加えてアプリのDocumentsへ追記し、画面から書き出せる。追記・書き出しの失敗は画面に出す | 試験中にアプリが終了しても、終了直前までの記録を残す |
| ロジックの分離 | 履歴の追加判定とログ整形は、UIKit・SwiftUIをimportしないファイルに置く | 画面なしで判定を検査できる形にする |

## 最初に行う動作確認

TestFlightで入れた最初の版で次を確かめる。1つでも通らなければ、端末・操作・エラー表示を記録する。

1. TestFlightから入れたアプリが、通常のウインドウとStage Managerの小窓で起動する。
2. `UIPasteboard`、`PasteButton`、ドラッグ、Documentsへの書き込みを使うコードが、GitHub Actionsでビルドできる。
3. `PasteButton` で文章を1件保存できる。自動収集の許可を拒否した後も保存できるかを見る。
4. 項目をメモへドラッグできる。タップでコピーした後、メモで通常の貼り付けができる。
5. ログをDocumentsへ追記し、書き出して持ち帰れる。

## 収集と再利用の設計

- **記録の開始。** 自動収集を初めて有効にするとき、他アプリのコピー内容を読む許可が求められる場合があることを説明する。開始時点の `changeCount` を基準にし、開始前からクリップボードにあった内容は読まない。必要なら手動保存を使う。
- **2方式を別々の試行として比べる。** (a) `UIPasteboard.changedNotification` だけを使う。(b) 記録中に `changeCount` を一定間隔で確認する。間隔の初期値は0.5秒で、画面から変更できる。どちらの方式も全コピーの取得を保証しない。確認の間に2回コピーされた場合、間の1件は取り戻せない。`changeCount` の差を欠落件数として扱わず、欠落は期待した一覧との照合で数える。
- **sceneが非アクティブのとき。** 記録中は監視を止めず、その間に何が届いたかをログに残す。アクティブへ戻ったときに `changeCount` を1回確認し、変わっていれば読み取る。この読み取りは「復帰時」として区別する。
- **読み取り。** `changeCount` が前回と違うとき、`hasStrings` を確かめてから `string` を読む。`hasStrings` は文章の有無を調べるだけで、読み取りの許可を得る操作として扱わない。`hasStrings` の結果、読み取りの結果、読み取り前後の `changeCount`、所要時間を別々に記録する。読めなかった理由を区別できない場合は「取得できず・原因未確定」と記録する。
- **手動保存。** SwiftUIの `PasteButton` を使う。
- **タップでコピー。** 項目のタップで `UIPasteboard.general` に文章を書き、「コピーしました」と表示する。入力先への貼り付け成功は表示しない。
- **ドラッグ。** 項目から文章をドラッグで持ち出せる。
- **履歴への追加判定。** 「直前の内容」を1つだけメモリに持つ。読み取りに成功したとき、または自分で書き込んだときに、その文章で上書きする。新しく読み取った文章が直前の内容と同じなら行を追加せず、見送った理由をログに残す。違えば追加する。番号は保存しない。
- **この判定で区別できない場合。** 同じ文章を外部で続けてコピーした場合と、自己コピーの直後に別アプリが同じ文章をコピーした場合は、1回分しか残らない。20件の主試験は互いに異なる文章で行い、同じ文章の扱いは別の試験で評価する。手順2の重複整理で規則を決め直す。
- **状態の表示。** 「記録を開始した・停止した」と「現在のscene状態」を別々に表示し、ログにも別々に残す。scene状態から取得できるかどうかを推定して表示しない。
- **削除。** 履歴は1件ずつ、または全部を消せる。ログの消去は別の操作にし、メモリとDocumentsの両方から消す。それぞれ何が消えるかを画面に書く。書き出し済みのログはアプリから消せないことも書く。

## 実機試験の記録

### 2026年11月14日 ビルド3（iPad Air 13インチ、iPadOS 27.2.1）

利用者の報告と、書き出したログ（119行）から分かったこと。

- **通知方式は、他のアプリのコピーを検知しなかった。** 記録中にSafariで少なくとも9回コピーされ、changeCountは64から73まで増えた。しかし `UIPasteboard.changedNotification` は1回も届かなかった。clipboard+がactiveのままSafariで4回コピーした区間（14:27〜14:29）でも0回だった。
- **許可のダイアログは、復帰時の自動読み取りで出た。** ペーストボタンでclipboard+がactiveに戻った直後に、復帰時の確認が `string` を読み、そのたびにダイアログが出た。設定アプリで「他のAppからペースト」を許可すると、出なくなった。復帰時の読み取りは7〜14ミリ秒で成功した。
- **inactiveへの変化は、ペーストボタンや許可のダイアログの操作と重なっていた。** Safariでコピーしただけの区間ではactiveのままだった。当初「Safariを操作するとinactiveになる」と分析したが、2回目の試験で否定された。
- **ドラッグではダイアログが出なかった。** タップでコピーしてメモへ貼り付けると、ダイアログが出た。その時点で記録は停止していたので、メモ側が出したものと推定する（ダイアログの文言は未確認）。
- **定期確認方式（0.5秒間隔）は、Safariでの3件をすべて取り込んだ。** 「他のAppからペースト」を許可した状態で、clipboard+に触れずにコピーした。3件とも次の確認で検知し、読み取りは30〜34ミリ秒で成功した。許可のダイアログは1回も出なかった。sceneは記録中ずっとactiveだった。
- この結果を受けて、収集方式の初期値を定期確認に変えた。

### 20件試験（同日、ビルド3、定期確認0.5秒、ペースト許可済み）

[試験用ページ](https://shingoto1112.github.io/clipboard-plus/)で、番号付きの20件を約1秒間隔でコピーした。ページは押した時刻をミリ秒で表示する。

| 条件 | 結果 |
| --- | --- |
| ウインドウ表示App（Safariとclipboard+を並べる） | **20件中20件を、順番どおり1回ずつ取り込んだ。** changeCountは108〜127と1ずつ増え、各値を1回ずつ検知して読み取った。各件の文字数が試験01〜20の文字数と順に一致した。押した時刻から検知までは52〜502ミリ秒、読み取りは23〜29ミリ秒。許可のダイアログは出なかった。コピー間隔の最短は約0.8秒 |
| 全画面（clipboard+を表示しない） | clipboard+はbackgroundで止まり、その間の20件は取り込めなかった。clipboard+に戻った時点で、最後の1件（試験20）だけを取り込んだ |

- inactive（小窓を表示中で、操作対象ではない状態）でも定期確認は動き、読み取れた。
- 画像のコピー（スクリーンショット）は `hasStrings=false` となり、読み取らなかった。ログの表示は「取得できず・原因未確定」で、文章以外と区別できない。

**判定。** ウインドウ表示Appでは、手順1の合格条件（20件が順番どおり各1回残る、途中の1件をメモで再利用できる、許可操作を繰り返さない）を満たした。メモでの再利用は、最初の試験でドラッグで確認した。

### 速い連続コピー（同日、定期確認0.5秒）

試験用ページで20件を約6.8秒で押した。押す間隔は多くが0.22〜0.38秒だった。履歴に残ったのは12件で、8件を取りこぼした。順番の入れ違いと重複はなかった。確認の間に2回以上コピーされると最後の1件しか見えない、という設計どおりの結果。約1秒間隔なら全件を取り込めている。

**残っている確認。**

- Stage Managerでの20件試験。
- 定期確認の間隔を0.1秒にしたときの、速い連続コピーでの取り込み件数。結果によって初期値を見直す。
- 通知方式は他のアプリのコピーを検知しなかったため、収集方式から外す。

## 計測ログ

1行に、時刻（ミリ秒）、種別、`changeCount`、scene状態、文字数、対応する履歴の番号を記録する。原文は既定では記録しない。画面のスイッチで有効にしたときだけ、文章の冒頭を含める。

種別は、通知受信、定期確認での検知、復帰時の確認、`hasStrings` の結果、読み取り成功、取得できず、手動保存、自己コピー、追加の見送り、scene状態の変化、記録の開始・停止、削除、ログ書き込みの失敗。

許可ダイアログの表示回数をアプリから数える方法は確認できていない。利用者が目視で数え、試行ごとに書き留める。

## 試験の手順

試験には、番号の入った架空の文章を使う。実際の作業で使う文章や秘密の情報はコピーしない。

1. **主試験。** 番号付きの文章20件を、Safariから約1秒間隔で順にコピーする。表示方式（通常のウインドウ、Stage Manager）と収集方式（通知、定期確認）の組み合わせごとに1試行とする。
2. **試行ごとに書き留める項目。** 許可設定、表示方式、収集方式、開始・終了時刻、目視した許可ダイアログの回数、履歴に残った番号の並び、欠落と重複。
3. **再利用。** 途中の1件について、メモへのドラッグと、タップでコピーした後の通常の貼り付けを両方試す。
4. **短い間隔。** 主試験とは別の試行として、間隔を詰めてコピーし、ログから実際の間隔を読む。
5. **同じ文章。** 「A→自己コピー→外部B→外部A」「同じ文章を外部で続けてコピー」「自己コピーの直後に外部で同じ文章をコピー」を試す。
6. **自動収集が失敗した条件。** 同じ条件で手動保存を試し、代わりに使える範囲を書く。

アプリのログには、アプリが気づかなかったコピーは残らない。欠落は、コピーした番号の一覧と履歴を照らして数える。
