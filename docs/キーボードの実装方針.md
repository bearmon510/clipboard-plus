# clipboard+ 専用キーボード・共有拡張の実装方針（段階5の1・2）

2026年11月18日。[専用キーボードの方針](キーボードの方針.md)（2026年11月18日決定）に基づき、段階5の1（署名の確認の準備）と2（共有の土台）の仕様をまとめる。

11月14日の試作（`git stash`）を土台にしつつ、0.15.0 のデータ層（履歴とテンプレートの分離）、iPhone・iPad 両対応、共有拡張の追加、および「フルアクセスは許可し、オフでも履歴・テンプレート挿入は動くようにする」という11月18日の決定に合わせて見直した。

## 範囲

今回の範囲（段階5の1・2）：
- ターゲット追加：`ClipboardPlusKeyboard`（キーボード拡張、最小UI：地球儀キーと「準備中」）と `ClipboardPlusShare`（共有拡張、最小実装：受け取った文章・URLを受け取り箱に入れて閉じる）を `app/project.yml` に追加し、本体に埋め込む。iPhone・iPad両対応（`TARGETED_DEVICE_FAMILY: "1,2"`）。キーボードの `RequestsOpenAccess` は `true`。
- ワークフロー修正：`ios-build.yml`（署名なしで拡張を含めてビルドとテスト）と `ios-testflight.yml`（拡張の Bundle ID・App Group を本番IDから生成し、確認用入力 `upload` を追加）。
- 共有の土台：本体からキーボード用一覧 JSON（`keyboard-history.json`）の書き出し、拡張から本体への受け取り箱（`inbox/`）、設定「キーボードを開いたときのタブ（履歴／テンプレート）」（`keyboard-settings.json`）、`app/Shared/` の共通型、単体テスト。

次の作業（段階5の3〜5）：キーボード本体の履歴・テンプレート一覧と挿入UI、簡易英数字面、フルアクセス時の「今のコピーを保存」、共有拡張のUI調整。

## 識別子と App Group の作り方

公開リポジトリには Team ID、正式な Bundle ID、App Store Connect のアプリIDを書かない。`app/project.yml` には仮のベース値（`APP_BUNDLE_ID: example.clipboardplus`）だけを置き、各識別子をビルド設定から組み立てる。

| 対象 | Bundle ID / 識別子 | 説明 |
| --- | --- | --- |
| 本体（`ClipboardPlus`） | `$(APP_BUNDLE_ID)` | 本体アプリ |
| キーボード拡張（`ClipboardPlusKeyboard`） | `$(APP_BUNDLE_ID).keyboard` | `com.apple.keyboard-service`、`RequestsOpenAccess = true` |
| 共有拡張（`ClipboardPlusShare`） | `$(APP_BUNDLE_ID).share` | `com.apple.share-services`（文章とWeb URL1件を受理） |
| テスト（`ClipboardPlusTests`） | `$(APP_BUNDLE_ID).tests` | 単体テスト |
| App Group | `$(APP_GROUP_ID)`（既定は `group.$(APP_BUNDLE_ID)`） | 3ターゲット共通の `com.apple.security.application-groups` |

- 3ターゲットの entitlements（`ClipboardPlus.entitlements`、`ClipboardPlusKeyboard.entitlements`、`ClipboardPlusShare.entitlements`）に `$(APP_GROUP_ID)` を指定する。
- 3ターゲットの `Info.plist` には `ClipboardPlusAppGroup = $(APP_GROUP_ID)` を入れる。
- `SharedAppGroup`（`app/Shared/SharedAppGroup.swift`）は `Bundle.main` の `ClipboardPlusAppGroup` を読み、空や未展開の `$(...)`、およびテストホスト環境（`XCTestConfigurationFilePath` があるとき）では `nil` を返す。App Group がない署名なしビルドやテストでは、共有コンテナ処理は静かに何もしない。
- 共有拡張・キーボード拡張では `app/Shared/CaptureIntents.swift` を `excludes` で除外し、`AppEnum` の重複登録を防ぐ。

## 共有コンテナのファイル形式

### 1. キーボード用一覧（`keyboard-history.json`）

本体（`HistoryStore` の直列キュー）が、起動時（`load`）および履歴・テンプレートの変更時に `KeyboardHistoryBuilder` で組み立て、`KeyboardHistoryFile.write` により `[.atomic, .completeFileProtectionUntilFirstUserAuthentication]` で丸ごと置き換える。

- **型（`KeyboardHistory`）：** `formatVersion`（`1`）、`exportedAt`（Unixミリ秒）、`entries`（`[KeyboardHistoryEntry]`）。
- **項目（`KeyboardHistoryEntry`）：** `id`、`kind`（`text` / `url`）、`text`、`lastCollectedAt`、`isTemplate`、`title`、`tag`、`templateOrder`。
- **対象：** 文章とURLのみ（PC同期で届いた `.pc` の項目とテンプレートも含む）。画像・ファイル・取り消し待ちは除外する。
- **並びと上限（メモリ制約対策）：**
  - 履歴（`isTemplate == false`）は新しい順（`lastCollectedAt` 降順、同値は `id` 降順）で最大 **300件**。
  - テンプレート（`isTemplate == true`）はアプリ本体と同じくタグの自然順（「その他」は末尾）とグループ内の並び順で最大 **300件**。
  - 全体の上限は UTF-8 合計 **2,000,000バイト（2MB）**（`text`・`title`・`tag` の合計）。単体で2MBを超える項目は除外し、合計が超える場合は履歴の古い末尾から削り（新しい方の連続性を保つ）、それでも超える場合はテンプレート末尾から削る。
  - 書き出し内容が前回と変わっていなければディスク書き込みを省く。

### 2. 拡張から本体への受け取り箱（`inbox/<UUID>.json`）

共有拡張やキーボード（段階5の4以降）が取得した文章・URLを1件1ファイルで置き、本体が取り込む仕組み。

- **型（`SharedInboxItem`）：** `formatVersion`（`1`）、`id`（`UUID`）、`text`、`createdAt`（Unixミリ秒）、`origin`（`keyboard` / `shareExtension`）。
- **書き込み（`SharedInbox.write`）：** `inbox/<UUID>.json` へ `[.atomic, .completeFileProtectionUntilFirstUserAuthentication]` で保存する。
- **取り込み（`HistoryStore.importSharedInbox`）：**
  - 本体の起動時（`ClipboardMonitor.init`）と前面復帰時（`updateScene("active")`）に実行する。
  - `SharedInbox.scan` で `.json` ファイルを読み（`createdAt` 昇順、`id` 順。ファイル時刻のPrivacy APIは使わない）、読めない／壊れたファイルは削除する。
  - 取り込んだ `id` は直近500件を `UserDefaults` に記録し（`Defaults` がない場合はメモリ保持）、すでに処理済みの `id` は履歴へ入れずファイルだけ消す（二重取り込み・PCへの二重送信の防止）。
  - 未処理の項目は `database.collect(item.text, source: .manual, at: item.createdAt)` で保存（既存の重複統合と同じく、同一本文は履歴1件にまとめる）し、`.upsert` と `.localEntry` を発火して PC 同期（`onLocalEntryForPC`）にも流したうえでファイルを削除する。
  - 計測ログには件数と取得元種別だけを記録し、原文やファイル名は出さない。

### 3. 開いたときのタブ設定（`keyboard-settings.json`）

- **型（`KeyboardSettings`）：** `formatVersion`（`1`）、`initialTab`（`KeyboardTab`: `history` / `templates`、既定は `history`）、`updatedAt`（Unixミリ秒）。
- **本体の設定画面：** `SettingsView` の「キーボード」に「開いたときのタブ（履歴／テンプレート）」を置く。変更は `UserDefaults` に保存するとともに `HistoryStore.setKeyboardInitialTab` 経由で `keyboard-settings.json` へ原子的に書き出す。起動時の `load` でも同期する。
- **拡張側：** `KeyboardSettingsFile.initialTab(from:)` で共有コンテナから読む（未設定・読み込み失敗時は `history`）。

## 署名の確認の手順（`upload=false`）

`ios-testflight.yml` の `workflow_dispatch` に入力 `upload`（真偽値、既定 `true`）を追加した。

1. GitHub Actions の「Upload iPad app to TestFlight」（`.github/workflows/ios-testflight.yml`）を手動実行する際、`upload` を **`false`** にして実行する。
2. ワークフローは `CLIPBOARD_PLUS_BUNDLE_ID` から `APP_BUNDLE_ID` と `APP_GROUP_ID=group.$CLIPBOARD_PLUS_BUNDLE_ID` を組み立て、`-allowProvisioningUpdates` 付きで `archive` を実行する。
3. 続けて `ExportOptions.plist` の `destination` を `export` にし、`xcodebuild -exportArchive` で配布用の署名・`.ipa` 書き出しまでを実行する。App Store Connect へのアップロードと `distribute-internal`（内部テストグループへの追加）は行わない。
4. 開発用証明書の取り消し、APIキーの削除、ログの伏せ字、署名関連ファイルを成果物にしない扱いは `upload=true` と同じく実行される。

### 自動署名で失敗した場合に Apple Developer サイトで登録が必要なもの

`-allowProvisioningUpdates`（App Store Connect APIキーによる自動署名）で App Group や拡張のプロファイル生成に失敗した場合は、利用者が Apple Developer サイト（Certificates, Identifiers & Profiles）で次を登録する：

1. **App Group ID：** `group.<本番のBundle ID>` を Identifiers → App Groups に作成する。
2. **拡張の App ID：** `<本番のBundle ID>.keyboard` と `<本番のBundle ID>.share` が自動作成されていなければ登録する。
3. **App Groups の紐付け：** 本体・キーボード・共有拡張の3つの App ID すべてで「App Groups」を有効にし、`group.<本番のBundle ID>` を選択して保存する。

## 検証

- 単体テスト（`app/ClipboardPlusTests/KeyboardFoundationTests.swift`）：一覧の組み立て・JSON往復・上限（300件／2MB）・添付と削除待ちの除外、PC同期由来の取り込み対象化、受け取り箱の読み込み・PC同期通知・ファイル削除・`UUID` による重複防止、初期タブ設定の書き出し・読み取り、共有コンテナ不可時の無害動作を確認する。
- CI（`ios-build.yml`）：署名なしでシミュレータ・実機の両方をビルドし、本体・`ClipboardPlusKeyboard.appex`・`ClipboardPlusShare.appex` の埋め込みと `Info.plist`、およびシミュレータでの単体テストを通す。
- 実機・署名の確認：Mac・Xcode が手元にないため、コンパイルと署名の確認は GitHub Actions（`ios-build.yml` と `ios-testflight.yml` の `upload=false`）で行う。
