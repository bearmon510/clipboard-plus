# clipboard+ 切り取りモードの実装方針

2026年11月15日。利用者が方針を2つ変えた。この文書は、その前提で切り取りの機能を作り直すための実装方針である。0.7.0で作った切り取り（[画面の切り取り](画面の切り取り.md)）は、ここに書く形へ置き換える。

## 変わった前提

1. **PiPはいったん使わない。** clipboard+は、Slide Over、ウインドウ表示App、Stage Managerの小窓として、画面に出した状態で使う。PiPは消さず、入口だけ残す（後述）。
2. **切り取りの流れを変える。** 利用者が決めた流れは次のとおり。

   ```
   文字か画像かを先に選ぶ → 切り取りモードに入る → 範囲を選び終える → クリップボードにコピーされる
   ```

   範囲を選んだ後に、もう一度ボタンを押す手順は置かない。指を離した時点で完了する。

## 全体の流れ

1. clipboard+の上部にある「文字で切り取る」か「画像で切り取る」を押す。
2. その時点の画面全体が、止まった絵としてclipboard+の窓に出る（切り取りモード）。
3. 絵の上をドラッグして範囲を選ぶ。指の近くに拡大鏡が出て、細かい位置を合わせられる。
4. 指を離すと完了する。
   - 文字：範囲の文字を読み取り、履歴に保存してクリップボードに入れる。
   - 画像：範囲をPNGにして、履歴に保存してクリップボードに入れる。
5. 切り取りモードが閉じ、元の画面に戻る。clipboard+は小窓なので、そのまま隣のアプリへ貼り付けられる。

## 画面の絵をどう手に入れるか

ほかのアプリの画面は、次の3つの経路でしか手に入らない。上から優先して使う。

| 経路 | 使える条件 | 手数 | 位置づけ |
| --- | --- | --- | --- |
| **A. ScreenCaptureKit** | iPadOS 27以降。Xcode 27でのビルドが必要 | ボタン1回（初回は許可の画面が挟まる） | 主経路。ショートカット不要 |
| **B. スクリーンショットの取り込み** | すべてのOS | iPadのスクリーンショット → 「コピーして削除」 | Aが使えないときの代わり |
| **C. ショートカット** | すべてのOS。最初に2手順のショートカットを作る | 割り当てた操作1回 | 0.7.0で作ったもの。残す |

### 経路A：ScreenCaptureKit

iPadOS 27で、アプリが画面全体を受け取る公式の仕組みが入った。Appleの資料と開発者フォーラムで次を確かめた（2026年11月15日）。

- 利用者がシステムの確認画面（`SCContentSharingPicker`）で許可すると、アプリは画面全体の映像（`SCStream`）を受け取れる。
- 専用の権限（entitlement）は要らない。配信用の拡張も要らない。
- 1枚だけ撮るAPI（`SCScreenshotManager`）はiPadOSでは使えない。映像の最新の1コマを使う。
- アプリが裏へ回ると映像は止まる。裏でも続けるには `UIBackgroundModes` に `screen-capture` が要る。

**映像を受け取る期間は「clipboard+が画面に出ている間」に限る。** 最初の切り取りで許可を求めて映像を始め、clipboard+が裏へ回ったら止める（`screen-capture` の裏での動作は使わない）。小窓で使う前提に合い、画面を取り込み続ける時間が最も短い。

- 受け取る映像は毎秒4コマ程度に抑え、メモリには最新の1コマだけを持つ。ディスクには書かない。
- 映像を受け取っている間は、上部のボタンに印を出す。メニューから手動でも止められる。
- 最後の切り取りから5分たったら、自動で止める。

許可の画面がどのくらいの手数か、どの頻度で出るかは、資料からは分からない。下の「実験で確かめること」で測り、結果によってこの方針を見直す。

### 経路B：スクリーンショットの取り込み

経路Aが使えない場合（iPadOS 26以前、許可しなかった場合、映像が始まらなかった場合）は、次の形にする。

1. 「文字で切り取る」か「画像で切り取る」を押すと、「スクリーンショットを撮って『コピーして削除』を選んでください」と案内して待つ。
2. 画像がクリップボードに入ると、clipboard+が取り込み、そのまま切り取りモードを開く。
3. 以降は経路Aと同じ。

待っている状態は、別の操作をするか30秒たつと解除する。

### 経路C：ショートカット

0.7.0の「画面を切り取る」アクションを残し、「文字」か「画像」を選ぶ項目を足す。開いた後の流れは経路Aと同じ。

## 切り取りモードの画面

- **止まった絵。** 受け取った画面を窓いっぱいに出し、少し暗くする。選んだ範囲だけ明るく抜く。
- **上部。** 「文字｜画像」の切り替えと、閉じるボタン。入る前に選んだ方が選ばれている。入った後でも切り替えられる。
- **範囲の選択。** ドラッグで選ぶ。指を離すと完了する。0.7.0にあった、角を引いて直す操作と、下のボタンはなくす。
- **拡大鏡。** ドラッグ中、指の少し上に拡大鏡を出す。指の位置の周りを実際の画面と同じ大きさで映し、十字の印で位置を示す。Slide Overのような狭い窓では、絵が実際の3割ほどに縮むため、これがないと細かく選べない。
- **小さすぎる範囲。** 指をほとんど動かさずに離した場合は、何もしない（誤タップで閉じないため）。
- **閉じる。** 閉じるボタンで、何もせずに戻る。

### 完了したとき

| 選んだもの | 処理 | 画面の反応 |
| --- | --- | --- |
| 画像 | 範囲をPNGにして履歴に保存し、クリップボードに入れる | すぐ閉じる。「画像をコピーしました」を出す |
| 文字 | 範囲の文字を読み取り、履歴に保存してクリップボードに入れる | 読み取り中は範囲に進行の印を出す。終わったら閉じ、「文字をコピーしました」と冒頭を出す |
| 文字（見つからない） | 何も保存しない | 閉じずに「文字が見つかりませんでした。もう一度選んでください」と出す |

保存した項目の取り込み方は「切り取り」とする（0.7.0と同じ）。文字の読み取りは、0.7.0のVisionによる処理をそのまま使う。

## clipboard+自身の写り込み

経路Aで受け取る絵には、画面に出ているclipboard+の窓も写る。

- **ウインドウ表示App、Stage Manager。** clipboard+は隣に並ぶので、ほかのアプリは隠れない。
- **Slide Over。** clipboard+がほかのアプリの上に重なるため、その下は絵に写らない。切り取りたい場所が隠れているときは、Slide Overを反対側へ動かしてから切り取る。この制限は案内に書く。

映像から自分の窓を外す方法があるかは、資料では確かめられなかった。実験で確かめ、外せるなら外す。

## 入口の配置

上部のバーを次のように変える。

```
[検索] [文字で切り取る] [画像で切り取る] [⋯]
```

- PiPのボタンを外し、その場所に切り取りの2つのボタンを置く。
- 一時停止はメニュー（⋯）へ移す。一時停止中は、今と同じオレンジの帯を出し、帯を押すと再開する。
- 履歴の画像の「⋯」には「文字で切り取る」「画像で切り取る」を置く。保存済みの画像を絵として、同じ切り取りモードを開く。画像全体の「文字を読み取る」は残す。

## PiPの扱い

- 初期状態でオフ。上部のボタン、空の状態での案内、設定の「収集」からは外す。
- 設定の「開発者向け」に「PiPで裏でも収集（試験的）」を残す。オンにしたときだけ、今のPiPの機能が働く。
- すでにオンにしている端末では、この版への更新時に1回だけオフへ戻す。
- PiPのコードとテストは残す。

小窓を隠している間や、全画面で別のアプリを使っている間は、収集しない。戻ったときに最後の1件だけ取り込む（PiPより前と同じ）。

## 開発環境

経路AにはiOS 27のSDKが要る。今のCIはXcode 26.6（iOS 26のSDK）である。

- **Xcode 27へ移す。** GitHub Actionsの `xcode-27` ランナー（Xcode 27.1）で、今のアプリをそのままビルドできることを確かめた（2026年11月15日、実行番号43698655875）。テストは223件中222件が成功した。失敗した1件は、後始末の完了を5秒待つテストの時間切れで、以前にも負荷の高いときに一度起きている。待ち時間を延ばして直す。
- 対応OSはiPadOS 17以降のままにする。経路Aのコードは、iPadOS 27以降でだけ動くように分ける。それより前のOSでは経路Bを使う。
- `ios-build.yml` と `ios-testflight.yml` の両方を `xcode-27` へ移す。
- `Info.plist` に、画面を取り込む理由の説明（`NSScreenCaptureUsageDescription`）を足す。

## 作る順序

### 段階1：実験ビルド（0.8.0）

経路Aが実機でどう動くかを確かめるための、最小の版。PiPのときと同じく、先に事実を集める。

- Xcode 27への移行と、時間切れするテストの修正。
- PiPを初期状態でオフにし、入口を「開発者向け」へ移す。
- 経路Aの取り込み（許可、映像の受け取り、最新の1コマ、裏へ回ったときの停止、5分での自動停止）。
- 上部の2つのボタンと、新しい切り取りモード（先に選ぶ、指を離すと完了、拡大鏡）。
- 計測ログに、許可の結果、映像の開始と停止とその理由、最初の1コマが届くまでの時間、絵の大きさを記録する。

### 段階2：仕上げ（0.8.x）

実験の結果を反映する。

- 許可の持続の方針を確定する（下の判断の基準）。
- 経路Bの案内と自動での切り取りモード、経路Cの「文字／画像」の項目。
- 使い方の案内の書き直し。
- 狭い窓での選びやすさの調整。

## 実験で確かめること

| 確かめること | 見るもの |
| --- | --- |
| 許可の画面の手数 | 「画面全体」を選ぶまでに何回押すか。待ち時間があるか |
| 許可が出る頻度 | 切り取りのたびか、映像を始めるたびか、アプリの起動ごとか |
| 録画中の表示 | どこに、どのように出るか。邪魔になるか |
| 自分の窓の写り込み | clipboard+の窓が絵に写るか。Slide Overの下がどう写るか |
| 絵が届くまでの時間 | ボタンを押してから切り取りモードが出るまで |
| 小窓を隠したとき | 映像が止まるか。出し直したときに再び許可が要るか |
| ほかのアプリへの影響 | 動画配信などが、取り込み中に内容を隠すか |
| 狭い窓での選びやすさ | Slide Overの幅で、拡大鏡を使って目的の範囲を選べるか |
| 文字の読み取り | 日本語の精度と、かかる時間 |

## 判断の基準

- **許可が1回の操作で済み、映像を始めるたびに出る場合：** 方針どおり「画面に出ている間だけ」にする。
- **許可に複数回の操作や待ち時間が要る場合：** 設定に「切り取りの準備を保つ」を足す。オンにすると、裏でも映像を続け（`screen-capture`）、小窓を出し直しても許可なしで切り取れる。録画中の表示が出続けることを設定に明記する。初期値はオフ。
- **狭い窓で、拡大鏡があっても選びにくい場合：** 切り取りモードを別の大きな窓で開く方法か、絵をピンチで拡大する操作を足す。
- **経路Aが実用にならない場合**（映像が始まらない、絵が届くのが遅い、多くのアプリが内容を隠す）：経路Bを主経路にする。

## 合格条件

1. Slide Over、ウインドウ表示App、Stage Managerのそれぞれで、「文字で切り取る」を押して範囲を選ぶと、その範囲の文字がクリップボードと履歴に入る。
2. 同じく「画像で切り取る」で、その範囲の画像がクリップボードと履歴に入る。
3. 範囲を選んで指を離した後、追加の操作なしで元の画面に戻る。
4. 切り取りの後、隣のアプリへそのまま貼り付けられる。
5. clipboard+を隠すと、画面の取り込みが止まる。
6. 許可しなかった場合は、経路Bの案内に切り替わる。
7. PiPをオンにしていない状態で、これまでの収集・検索・ピン留め・削除・バックアップが変わらず動く。

## 検証

- 範囲と拡大鏡の計算、切り取りモードの状態の移り変わり（待ち → 絵がある → 選択中 → 処理中 → 完了／やり直し）、取り込みの開始と停止の条件は、単体テストで確かめる。映像の受け取りは差し替えられる形にし、テストでは偽の絵を渡す。
- 画面の見た目は、CIが保存する画像で確かめる（狭い窓と広い窓、拡大鏡が出ている状態、読み取り中、見つからなかった状態）。
- ScreenCaptureKitそのものの動作は、シミュレータでは確かめられない。実機で利用者が確かめる。

## 実装メモ（裏側）

- 0.8.0の `ScreenCaptureController` は指定の公開APIを維持した。`ScreenCaptureSource` 越しに映像を受け取り、テストでは供給元・時刻・タイマーの自動実行を差し替える。許可待ち・開始待ち・画像変換中の要求はまとめ、同じ結果を返す。停止後の古いイベントや画像変換結果はセッションの識別子で除外する。
- ScreenCaptureKit側は `#if canImport(ScreenCaptureKit)` と `@available(iOS 27.0, *)` で分離。毎秒4コマ、`queueDepth = 3`（公式資料の最小値）。最新のCVPixelBufferだけを保持し、要求時に専用キューと使い回すCIContextでUIImageへ変換する。向きは `.up`、scaleは1、出力ピクセル数は `filter.contentRect × pointPixelScale`。画面の画像はディスクへ書かず、音声・カメラ・録画ファイルの出力も作らない。
- 開始成功から0.6秒以降に届いた完全なコマだけを利用する。8秒の期限は最初の要求から数え、許可・開始・画像変換の待ち時間を含む。手動停止、`sceneDidChange(false)`、pickerの取り消し、streamのエラー、最後の利用から5分で停止してバッファを破棄する。一度も切り取りを完了しない場合も、開始から5分で停止する。変換中の一時参照は処理終了時に解放し、その結果を画面へ返さない。
- 計測ログは許可、開始、停止理由、エラーのdomain/code、最初の使用可能なコマまでの要求起点・開始起点のms、ピクセル数、filterの矩形と倍率だけを記録する。画像や原文、NSErrorのuserInfoは記録しない。クリップボードを読む処理ではないため、このログのchangeCountは0。
- Appleの[iOSサンプル](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-on-ios)、[picker](https://developer.apple.com/documentation/screencapturekit/sccontentsharingpicker)、[observer](https://developer.apple.com/documentation/screencapturekit/sccontentsharingpickerobserver)、[stream](https://developer.apple.com/documentation/screencapturekit/scstream)、[設定](https://developer.apple.com/documentation/screencapturekit/scstreamconfiguration)、[filter](https://developer.apple.com/documentation/screencapturekit/sccontentfilter)で、iOS 27対応と使用する宣言・開始手順を確認した。observerを登録してから `present()` を呼ぶ。マイク・カメラの切り替えは表示しない。`UIBackgroundModes` は既存のaudioだけで、screen-captureは追加しない。
- [allowedPickerModes](https://developer.apple.com/documentation/screencapturekit/sccontentsharingpickerconfiguration-swift.struct/allowedpickermodes)はiOS 27対応とある一方、[singleDisplay](https://developer.apple.com/documentation/screencapturekit/sccontentsharingpickermode/singledisplay)の個別ページにはiOS対応の記載がない。この不一致はSDKで未確認。未確認の定数を使わず、全種類を許す既定設定と、iOSサンプルの全画面用 `present()` を採用した。[excludedBundleIDs](https://developer.apple.com/documentation/screencapturekit/sccontentsharingpickerconfiguration-swift.struct/excludedbundleids)には実行中のBundle IDを指定するが、資料の説明は「pickerから除外」であり、全画面映像から自分の窓が消える保証は確認できていない。除外が効く前提で画像を加工しない。
- PiPはリソースを作る前に、版専用の移行キーで一度だけオフへ戻す。その後に利用者が再度オンにした設定は維持する。初期値オフと既存コードを残し、2つのトグルを設定の「開発者向け」へ移した。
- CIの既定・TestFlightビルドは `xcode-27`。通常のテスト対象をiOS 27のiPadに絞り、手動のmacos-26指定ではiOS 26を選ぶ。TestFlightの署名・伏せ字・証明書取り消しの処理は変更しない。バックアップ後始末のテスト待機は60秒に延長した。
- 偽の供給元によるテスト16件とPiP移行のテスト1件を追加。Windowsでは差分・参照・CIのシェル構文（5ブロック）・iOS 27のランタイム名との照合・TestFlightの変更がランナー名だけであることを確認した。Swiftコンパイル、XCTest、XcodeGen、画面描画は未実施であり、追加テストの成功は未確認。コミット・push・CI実行は行っていない。
- 実機では、全画面の選択、許可の頻度と8秒の期限、0.6秒後の許可画面の写り込み、実画面と出力の解像度・向き（取り込み中の回転も含む）、自分の窓の除外、静止画面でのコマ到着、小窓を隠した際の停止、再開始、5分の停止、メモリ・発熱を確認する。View側は `sceneDidChange` の引数に何を渡すか統合確認が必要。本コントローラーはfalseで許可待ちも含めて停止するため、システムpickerによる一時的なinactiveとの相互作用も確認する。
