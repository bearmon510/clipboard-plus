# 段階4の実装方針：PCの履歴の窓とWin+V

2026年11月18日。PCに clipboard+ 専用の履歴の窓を作り、キーで開いて、選んだ項目を元のアプリに貼り付ける。Windows自身のクリップボードの履歴（Win+V）の代わりに使えるようにする。

## 決めたこと（利用者の判断）

- 窓は、Windowsの Win+V の窓くらいの大きさにする。
- 開くキーの既定は Win+V。低レベルキーボードフックで、Windowsの履歴の代わりに開く。設定でオン・オフでき、左手で押せる2つのキーの組み合わせ（Ctrl+無変換など）にも変えられる。3つのキーは押しにくいので使わない。Fnキーは多くのキーボードでWindowsに伝わらないので使えない。

## 窓（Claudeが作る）

- 大きさは幅360・高さ460くらい。枠のない窓で、入力位置（取れないときはマウス）の近くに出す。画面の作業領域からはみ出さない。
- 上に検索欄。下に履歴を新しい順に並べる。文章は2行まで、画像は小さな画像、ファイルは名前を出す。各項目に、出どころ（PC・iPhone・iPad）と時刻を小さく出す。
- 操作：文字を打つと検索、↑↓で選ぶ、Enterかクリックで貼り付ける、Deleteで消す、Escで閉じる。右クリックで「コピーだけする」「削除」。窓の外を押すと閉じる。
- 選んだら、その項目をクリップボードに入れ、窓を閉じ、開く前の窓に戻して Ctrl+V を送る。設定「選んだら貼り付ける」をオフにすると、クリップボードに入れるだけにする。
- 履歴が変わったら（PCでのコピー、iPhone・iPadからの受信）、開いている窓にもすぐ出す。
- 明るい・暗い表示は、Windowsの設定に合わせる。

## キーと貼り付けの仕組み（Geminiが作る）

- 専用のスレッドでメッセージループを回し、そのスレッドで WH_KEYBOARD_LL を設置する。コールバックでは判定だけをして、すぐ返す（1秒を超えるとWindowsが黙ってフックを外す）。窓を開く処理はUIのスレッドに回す。
- 組み合わせは「修飾キー1つ（Win・Ctrl・Alt・Shift）＋ほかのキー1つ」の2つのキーだけ。設定に文字列で保存する（例："Win+V"、"Ctrl+NonConvert"）。
- 組み合わせが押されたら、修飾キーでないほうのキーの押下と離上を止める（Windowsや前面のアプリに渡さない）。Winを含むときは、何も起きない仮のキーを1つ送り、Winを離したときにスタートメニューが開くのを防ぐ。自分で送ったキーは、フックで素通りさせる。
- 設定で組み合わせを変えるときは、「記録」の状態にして、次に押された2つのキーの組み合わせを受け取る（Escでやめる）。
- 窓を開く直前に、手前の窓と入力位置（GetGUIThreadInfo のキャレット。取れなければマウスの位置）を覚える。貼り付けるときは、修飾キーが離されてから、手前の窓に戻して SendInput で Ctrl+V を送る。
- 管理者として動いているアプリが手前にあると、Windowsの決まり（UIPI）で、キーを受け取れず、貼り付けも送れない。そのときはWindowsの動きのままになる。説明に書く。
- 設定は `%LOCALAPPDATA%\clipboardplus\settings.json` に保存する：キーを使うか（既定オン）、組み合わせ（既定 Win+V）、選んだら貼り付けるか（既定オン）。

## つなぎ方

- `Infrastructure` に、キーのフック、手前の窓と入力位置の記録、貼り付けを置く。キーの組み合わせの解釈と判定は、WPFに依存しない形で `Core` に置き、`ClipboardPlus.Sync.Tests` で確かめる。
- App は、組み合わせが押されたら、手前の窓と入力位置を記録して、履歴の窓に渡す（`IHistoryPresenter.Present(HistoryInvocation)`）。履歴の窓が、選ばれた項目を `SyncCoordinator.CopyHistoryAsync` でクリップボードへ入れ、貼り付けの仕組みを呼ぶ。
- 組み直しで `SyncCoordinator` が替わっても、履歴の窓は新しいものを使う。
- タスクトレイのメニューに「履歴を開く」を足す。メインの窓に、キーの設定（使うか、組み合わせ、変える、既定に戻す）と「選んだら貼り付ける」を足す。

## 確かめ方

- キーの組み合わせの解釈と判定、設定の読み書きは単体テストで確かめる。
- 窓は、手元で画像に描き出して見た目を確かめる。
- フック、貼り付け、スタートメニューが開かないこと、管理者のアプリでの動きは、利用者のPCで確かめる（段階3と4をまとめたTestFlightのとき、PCのアプリも新しくする）。

## 2026年11月18日の見直し（動かせる履歴の窓・閉じやすさ・iOS寄せ・ドラッグ持ち出し）

実機報告を受け、履歴の窓の使い勝手と見た目を以下のとおり改めた。

- **動かせて大きさを変えられる窓**
  - 上部に細い見出しの帯（`clipboard+ 履歴` と閉じる `×` ボタン）を付け、帯のドラッグ（`DragMove`）で位置を動かせるようにした。
  - `ResizeMode="CanResize"` に変更し、最大化・最小化スタイルを外した上で `WM_NCCALCSIZE`（非クライアント枠を消す）と `WM_NCHITTEST`（端と角の5dp領域でリサイズ）を処理する。最小の大きさは幅 300・高さ 320。
- **位置と大きさの記憶・マルチDPI補正**
  - 閉じたとき／隠れたときの位置（画面座標）と大きさ（論理サイズ）を `AppSettings`（`settings.json` の `HistoryWindow`）に保存し、次に開くときに復元する。まだ保存値がない初回は従来どおりキャレットまたはカーソルの近くに出す。
  - モニターの取り外しや解像度・DPI変更により保存位置が画面外になった場合は、最も近い画面の作業領域へ戻し、その画面のDPI倍率で大きさを当てはめる。位置計算・検証・リサイズ境界・ドラッグしきい値の判定はWPFから切り離した `Core/HistoryWindowPlacement.cs` に置き、`ClipboardPlus.Sync.Tests` で確かめる。
- **閉じやすさと前面化の強化**
  - 見出しの `×` ボタン、`Esc`、窓の外のクリック（`Deactivated`）のいずれでも閉じる。
  - `ForegroundContext.BringToFront` を追加し、直接の `SetForegroundWindow` に失敗したときは `AttachThreadInput`（`BringWindowToTop`・`SetActiveWindow` 併用）、さらに必要なら `NativeInput` による `VK_MENU`（Alt）フォールバックで前面化を試みる（`SendAltUp` 時は前面化できなかった場合のみメニューマスクを添える）。
  - それでも前面に出られなかった場合は、表示中かつ非アクティブな間だけ `RegisterHotKey` で一時的に `Esc` を受け取り、`×` ボタンと `Esc` のどちらでも閉じられるようにした。窓がアクティブ化するか閉じるとすぐ解除する。
- **iOSのアプリに寄せた見た目**
  - 丸い検索欄（虫眼鏡・クリアボタン）、角丸カード、ホバー／選択の枠と背景色、種類（文章・リンク・メール・電話・色見本・画像・ファイル）に応じたアイコンと色分け、`⋯` メニューボタン、空状態・検索ゼロ件の案内を整え、Windows の明暗設定（`AppsUseLightTheme`）に合わせた。分類判定と表示補助は `Core/HistoryText.cs` に置いた。
  - テンプレートは同期プロトコル上 PC 側へ届いていないため、「履歴｜テンプレート」の切り替えは付けていない。
- **ドラッグアンドドロップ（窓から外へ）**
  - `SystemParameters` のドラッグ開始距離を超えて動かしたときだけ `DragDrop.DoDragDrop(..., DragDropEffects.Copy)` を開始し、ドラッグ開始時にクリック予定を消してクリック貼り付けと誤認しないようにした。
  - 文章はテキスト、画像は一時ディレクトリ（`drag/`）へ安全な拡張子付きで書き出したパスの `FileDrop` と `Bitmap` / `PNG` の両方、ファイルは安全なファイル名に整えた一時ファイルの `FileDrop` を渡す。1時間以上前の古い一時ファイルは開く際に掃除する。
  - ドラッグ中は `Deactivated` や `HistoryChanged` による一覧再構築でドラッグが途切れないよう抑止し、ドラッグ終了後に非アクティブなら窓を隠す。
  - 外から窓へのドロップは、`SyncCoordinator` にクリップボードのシーケンス番号（`lastClipboardSequence` / `ownSequence`）へ依存しないローカル追加の入口がなく、`SyncCoordinator.cs` が別作業と競合して触れないため今回は見送った。
