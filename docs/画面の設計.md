# clipboard+ 画面の設計（0.6.0）

2026年11月15日。利用者から「毎日使うものなので、使っていて気持ちのよい画面にしたい」という要望があり、主な画面を作り直した。それまでの画面は実機試験のための作りで、上部に操作が何段も並び、履歴は文字の行が続くだけだった。

## 考え方

毎日の操作は「ぱっと見る → 見つける → タップかドラッグ → 元の作業へ戻る」の繰り返しである。小窓の狭い幅で、この一連を短くすることを優先した。

- **履歴に場所を使う。** 上部は1段にまとめ、アプリ名や件数の表示はやめた。よく使う検索を大きく、たまにしか使わない操作（設定、全消去）はメニューへ入れた。
- **記録中は何も言わない。** 記録しているのが普通の状態なので、表示を出さない。一時停止したときだけ、オレンジの帯で知らせる。
- **中身で見分けられるようにする。** 種類ごとに見せ方を変える（下の表）。
- **手応えはその場に出す。** タップしたカードの上に「コピーしました」を出す。画面の別の場所へ目を動かさなくて済む。iPadには振動の仕組みがないため、手応えは見た目だけで伝える。
- **勝手に動かさない。** 新しい項目が入っても、スクロール位置は動かさない。入った項目は、枠を一瞬光らせて知らせる。

## 構成

上から順に並ぶ。

1. **上部のバー。** 検索欄、一時停止／再開、PiP、メニュー（設定、履歴の全消去）。
2. **状態の帯。** 一時停止中、PiPの準備中、保存の失敗など、知らせることがあるときだけ出す。
3. **絞り込み。** すべて／ピン留め／文章／リンク／画像。右端にペーストのボタン（今のクリップボードの内容を保存する）。
4. **履歴。** 「ピン留め」「今日」「昨日」「過去7日間」「それ以前」で区切ったカードの一覧。ピン留めの区切りはたためる。絞り込み中と検索中は、ピン留めを分けずに日付順に並べる。

窓の幅に合わせて、カードは1〜4列に並ぶ（1枚あたり約300pt以上）。複数列のときは、列ごとに詰めて並べ、高さの違うカードの間に隙間を作らない。

### カード

| 種類 | 見せ方 |
| --- | --- |
| 文章 | 冒頭を4行まで |
| リンク | サイト名を太字で、その後ろ（パスなど）を小さく |
| 画像 | 縮小画像。縦横のピクセル数と大きさを添える |
| 色コード（`#2E6BF0` など） | 色の見本 |
| メールアドレス、電話番号 | それぞれのアイコン |

色コード・メールアドレス・電話番号は、保存してある文章から表示のたびに判定する。データベースには種類として保存しない。

カードの下の行には、種類のアイコン、時刻、複数回コピーした場合の回数（×3）、ピン留めの印を出す。時刻は「たった今」「3分前」「14:02」「11/3 18:40」のように、新しいほど短く書く。

操作：タップでコピー、ドラッグで持ち出し。「⋯」か長押しで、コピー、全文を表示（画像は拡大表示）、リンクを開く、ピン留め、削除。

### 検索

一致した部分に色を付ける。長い文章の途中で一致した場合は、その少し前から表示する。検索語の前後の空白は無視する。

### PiPのボタン

小さな画面の形をしている。PiPを有効にすると、小窓の元になる映像がこのボタンの中に入る。AVKitは、PiPを始めるために元の映像が窓の中に見えていることを求めるため、ボタンそのものを映像の置き場所にした。

## 画面を画像で確かめる仕組み

開発用のPCではアプリを動かせず、これまで画面の見た目を確かめる手段がなかった。そこで、単体テスト `ScreenSnapshotTests` が主な画面を架空のデータで描き、PNGで保存する。GitHub Actionsがそれを成果物 `screen-snapshots` として残す。

撮る画面：狭い窓（360pt）の明るい表示と暗い表示、広い窓（1024pt）、検索中、一時停止中、履歴が空の状態、全文の表示。

確かめられるのは静止した見た目だけである。タップの手応え、新着の光り方、ドラッグ、PiPの開始は、実機で確かめる。

```sh
gh run download <実行番号> -n screen-snapshots -D <保存先>
```
