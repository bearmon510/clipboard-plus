# 画像履歴（0.3.0）の実装と確認

対象仕様は [段階3の実装方針](段階3の実装方針.md)。共有拡張、App Groups、OCR、動画、画像を含むバックアップと復元は対象外。

## 設計上の判断

- 元データと縮小画像は `Application Support/HistoryImages/` に保存する。ファイル名は収集ごとのUUID。元データの形式を保持し、縮小画像はImageIOで長辺480px以下のJPEGにする。テストは一時ディレクトリへ差し替える。
- ハッシュ計算、PNGへのフォールバック変換、復号・縮小、書き込み、コピー用の読み込みは `HistoryStore` の直列キューで行う。一覧は縮小画像のURLだけを別のバックグラウンドキューで読む。拡大表示もバックグラウンドで読み、表示用の長辺を2,560pxに抑える。GIFなどの表示は先頭画像、コピー・ドラッグは元の全データを渡す。
- 自己コピーは、既知のハッシュと書き込み直後の `changeCount` を保存用キューの `ImageAdmission` に登録する。直後の安定した読み取りが両方一致した場合だけ見送る。外部コピーで `changeCount` が進めば、同じハッシュでも数える。読み取り中の変更の再確認もハッシュで判定する。文章の `HistoryAdmission` は変更しない。
- DBへの記録に失敗した画像は、ファイル名・ハッシュ・サイズなどの情報だけを保存待ちに残す。元データを再試行用のメモリに保持しない。重複統合した際の余分なファイル、取り消し統合で不要になったファイル、保存を断念したファイルは削除する。
- 起動時は取り消し待ちを含むDBの全参照と、その時点の保存待ちファイルを保護して掃除する。完全削除された行はDBの削除通知から一覧にも反映する。DBがロールバックした場合は削除通知も戻す。ファイル削除の失敗は再試行し、DBへの保存を重複して実行しない。
- 上限は十進のMB（1件20,000,000 bytes、ピン留め以外の画像合計500,000,000 bytes）。件数は文章・URL・画像を合わせてピン留め以外1,000件。取り消し待ちは上限削除から除外し、ファイルを期限まで保持する。件数と合計バイト数の上限はDB初期化時に差し替えられる。
- 設定の画像件数・使用量は、取り消し待ちとピン留めも含むDB上の元データを集計する。縮小画像と未保存の待ち行列は含めない。取り消し期限後の掃除で減る。
- JSONは版2。画像は `image` オブジェクトにハッシュ・ファイル名・バイト数・寸法・形式を持つ。画像データやBase64は含めない。文章の既存キーは変更しない。書き出したJSONを自動収集から除外する既存処理も維持する。

版1から版2への移行は単一トランザクション。部分ユニーク索引は次の定義。

```sql
CREATE UNIQUE INDEX history_active_text ON history(text)
WHERE deletion_id IS NULL AND kind != 'image';

CREATE UNIQUE INDEX history_active_image ON history(image_hash)
WHERE deletion_id IS NULL AND kind = 'image';
```

## 検証状況

- 既存93件を保持し、32件を追加（合計125件）。テスト画像は `UIGraphicsImageRenderer` で生成し、画像ファイルをリポジトリに追加しない。
- Windows上のSQLiteで、Swiftソースから取り出した実際の移行SQLを実行。版1の行・ピン・回数の保持、画像の空文字と文章の空文字の共存、画像ハッシュの一意性、取り消し待ちとの共存、移行失敗時の版・列・索引のロールバックを確認した。
- `git diff --check` を確認。既存テストの変更はJSON版1→2とスキーマ版1→2の3か所のみ。
- この環境ではSwiftのコンパイル、XCTest、iPadシミュレータの画面確認は実行できていない。GitHub ActionsでXcode 26.6・Swift 5のビルドと125件のテスト実行が必要。コミット・push・Actionsの起動は行っていない。

主なAPIはApple公式資料で確認：
[PasteButton](https://developer.apple.com/documentation/swiftui/pastebutton)、
[NSItemProvider](https://developer.apple.com/documentation/foundation/nsitemprovider)、
[ImageIOの縮小読み込み](https://developer.apple.com/documentation/imageio/cgimagesourcecreatethumbnailatindex(_:_:_:))。

## 実機で確認すること

1. Safariの画像5枚とスクリーンショットを順番に収集し、画像とURLが同時に入る場合も画像だけが残ること。PNG・JPEG・HEIC/HEIF・GIF・TIFF・BMP・WebPの受け渡し、権限ダイアログ、読み取り時間をログで確認する。
2. 同じ画像の外部コピーは回数が増えること。履歴のタップコピー直後は時刻と回数が変わらず、メモへ画像としてペーストできること。
3. Safariからのドロップ、履歴からメモへのドラッグ、自分の履歴へのドロップ除外、ペーストボタンの画像・文章保存を確認する。
4. 再起動後も元データと縮小画像が残ること。削除→取り消しができ、期限後に使用量が減ること。
5. 幅360pt程度の小窓、Stage Manager、縦横両向きで、44pt以上の操作対象、行、拡大表示、ピンチ拡大、検索と絞り込みを確認する。スクロール中の新着で表示位置が勝手に動かないことも確認する。
6. 20MB超の画像で見送りの表示とサイズのログが残ること。大きな画像の読み取り中・コピー中の引っかかりとメモリ使用量を確認する。
7. 段階2の文章20件試験、統合、ピン留め、検索、削除・取り消し、ドロップ、JSON書き出し、書き出し内容の自動収集除外を再確認する。
